# سامانه هوش تجاری کلینیک دندان‌پزشکی

**پروژه پایانی درس هوش تجاری — دانشگاه صنعتی شریف**
**دانشجو:** فرهاد باقری طاهری

پنل مدیریتی کامل برای یک کلینیک دندان‌پزشکی: مدل داده، مولد داده مصنوعی،
API تحلیلی، داشبورد هفت‌صفحه‌ای فارسی و راست‌به‌چپ، دستیار هوشمند مبتنی بر
فراخوانی ابزار، و وب‌سایت عمومی کلینیک.

> داده‌های این مخزن **کاملاً مصنوعی** است — با `Faker("fa_IR")` و بذر ثابت ۴۲
> تولید شده و هیچ اطلاعات واقعی بیماری در آن نیست.

## پشته فناوری

| لایه | فناوری |
|---|---|
| مدل داده | DBML (۱۳ موجودیت) — رندر در dbdiagram.io |

| پایگاه داده | MongoDB 7 |

| پنل | React 18 + Vite + Tailwind CSS + Vazirmatn |

| استقرار | Docker Compose + nginx |

## راه‌اندازی سریع (Docker)

```bash
cp .env.example .env      # سپس همه مقادیر را تغییر دهید
docker compose up -d --build
```

| سرویس | آدرس |
|---|---|
| پنل مدیریت | http://localhost:8080 (نیازمند ورود) |
| وب‌سایت عمومی | http://localhost:3000 |

مقادیری که **حتماً** باید در `.env` تنظیم شوند:

```bash
SESSION_SECRET=$(openssl rand -hex 32)    # کلید امضای نشست
API_DB_PASSWORD=$(openssl rand -hex 24)   # حساب کم‌دسترسی API
MONGO_ROOT_PASSWORD=...                   # حساب ریشه مونگو
ADMIN_PASSWORD=...                        # ورود به پنل
```

نام کاربری و رمز پنل فقط با حروف و ارقام انگلیسی پذیرفته می‌شود؛ هم seeder
و هم فرم ورود این قانون را بررسی می‌کنند، چون حسابی که با حروف فارسی ساخته
شود هرگز قابل استفاده نخواهد بود.

## اجرای محلی (بدون Docker)

```bash
# ۱. مونگو
mongod --dbpath ~/.local/share/dental-mongo --port 27017

# ۲. بارگذاری داده
DATA_DIR=./data MONGO_URL=mongodb://127.0.0.1:27017 .venv/bin/python seeder/seed.py

# ۳. API
.venv/bin/uvicorn app.main:app --port 8000 --app-dir backend --reload

# ۴. پنل
npm run dev --prefix frontend        # http://localhost:5173
```

در حالت محلی Vite مسیر `/api` را به بک‌اند پراکسی می‌کند تا مرورگر روی یک
مبدأ بماند و کوکی نشست same-origin باشد — همان شکلی که در تولید nginx
انجام می‌دهد.

## صفحات داشبورد

| صفحه | پرسشی که پاسخ می‌دهد |
|---|---|
| داشبورد | نمای کلی، روند ماهانه، شاخص‌های سرصفحه |
| درآمد و خدمات | کدام خدمت واقعاً پول می‌سازد — **درآمد هر ساعت یونیت**، نه درآمد ناخالص |
| عملکرد پزشکان | درآمد، کمیسیون، **سهم خالص کلینیک**، درآمد هر ساعت یونیت، نرخ لغو و غیبت |
| عملیات | نرخ لغو و غیبت، نقشه حرارتی ساعات، بهره‌وری یونیت، **هزینه نوبت ازدست‌رفته به تومان** |
| طرح درمان و فراخوان | نرخ پذیرش، **درمان تأییدشده‌ی انجام‌نشده**، فهرست تماس بیماران لغزیده |
| مالی و انبار | زنجیره صورتحساب ← بیمه ← وصول، روش پرداخت، بهای مواد، موجودی |
| سودآوری و مطالبات | **حاشیه سود هر خدمت**، ساختار هزینه، تخفیف پنهان، **سن مطالبات و DSO** |

چند شاخص عمداً برخلاف گزارش‌های معمول محاسبه شده‌اند:

- **درآمد به ازای ساعت یونیت** — رتبه‌بندی بر پایه درآمد ناخالص، خدمتِ ارزانِ
  پرتکرار را ستاره نشان می‌دهد؛ تقسیم بر زمانی که از یونیت می‌گیرد نشان
  می‌دهد چه چیزی واقعاً از ظرفیت پول می‌سازد.
- **حاشیه سود هر خدمت** — درآمد منهای مواد مصرفی و کمیسیون. جدول از
  کم‌حاشیه به پرحاشیه مرتب شده، چون پرکارترین خدمت در صدر گزارش‌های درآمدی
  می‌نشیند و ممکن است کمترین سود را بسازد.
- **نرخ وصول هم‌گروه** — پرداخت‌ها با فاکتورهای *همان بازه* تطبیق داده می‌شوند.
  تقسیم نقد دریافتی بر مبلغ صورتحساب همان ماه دو جمعیت متفاوت را مقایسه
  می‌کند و نرخ وصول بالای ۱۰۰٪ می‌سازد.
- **بهره‌وری یونیت** — مخرج از `clinic_capacity` می‌آید، نه از «تعداد یونیت ×
  ساعات کاری»؛ یونیت‌ها شیفت یکسان ندارند.

## فیلترهای سراسری

پنج فیلتر — بازه تاریخ، تخصص پزشک، دسته خدمت و شرکت بیمه — روی همه صفحات
مشترک‌اند و با تعویض صفحه حفظ می‌شوند.

بعضی ترکیب‌ها **ذاتاً غیرممکن‌اند** و به‌جای تقریب‌زدن، اعلام می‌شوند:

- نوبتِ لغوشده **جلسه‌ای ندارد**، پس خدمت و دسته‌ای هم ندارد. اعمال فیلتر
  «دسته خدمت» روی نمودار لغو نوبت، دقیقاً همان ردیف‌هایی را حذف می‌کند که
  نمودار برای شمردن‌شان ساخته شده و نرخ غیبت ۱۲٪ را صفر نشان می‌دهد.
- یک فاکتور کل طرح درمان را پوشش می‌دهد که معمولاً چند دسته را در بر می‌گیرد،
  پس دسته‌ی یکتایی برای تطبیق وجود ندارد.

`UNSUPPORTED_FILTERS` این موارد را نام می‌برد، API آن را به کلاینت می‌دهد و
زیر همان نمودار توضیح داده می‌شود. آزمون
`test_declared_unsupported_filters_are_really_ignored` بررسی می‌کند هر مدخل
این نگاشت **واقعاً درست باشد** — تا توضیحی که به کاربر نشان داده می‌شود از
رفتار واقعی پایپ‌لاین جدا نیفتد.

## دستیار هوشمند

قانون طراحی: **دستیار محاسبه نمی‌کند.** هر عدد از `app/repositories` می‌آید —
همان تجمیع‌هایی که داشبورد رندر می‌کند — تا هر پاسخ با صفحه‌ای که از آن آمده
قابل مقایسه باشد. اگر مدل کوئری خودش را بنویسد، اعدادش با پنل اختلاف پیدا
می‌کند و اولین باری که مدیر این را ببیند به هر دو بی‌اعتماد می‌شود.

- بازیابی متن (`search_documents`) فقط برای توضیح است، هرگز برای عدد.
- دامنه پاسخ به کلینیک محدود است؛ پرسش بیرون از حوزه را رد می‌کند.
- شناسه مدل بالادست نه در UI و نه در `/api/chat/status` نمایش داده می‌شود.

بدون `AVALAI_API_KEY` بقیه پنل عادی کار می‌کند و فقط تب گفت‌وگو غیرفعال است.

## امنیت

| کنترل | پیاده‌سازی |
|---|---|
| رمز عبور | scrypt با پارامترهای درون‌خطی؛ مقایسه در زمان ثابت |
| شمارش کاربر | هش ساختگی برای کاربر ناموجود، تا زمان پاسخ یکسان بماند |
| نشست | JWT در کوکی httpOnly + SameSite=Lax |
| جستجوی فراگیر رمز | قفل ۱۵ دقیقه‌ای پس از ۵ خطا، به تفکیک (کاربر، IP) در مونگو |
| نقش‌ها | حذف فیلد در **کد** (`app/core/redaction.py`)، نه در پرامپت |
| هدرها | CSP، `frame-ancestors 'none'`، nosniff، Referrer-Policy |
| دسترسی پایگاه داده | API با حساب کم‌دسترسی وارد می‌شود، نه با حساب ریشه |
| کمینه‌سازی داده | فهرست بیماران `allergies` و `birth_date` را نمی‌فرستد |

تفکیک مهم: **کنترل دسترسی در کد است، نه در پرامپت.** محدودسازی افشای تلفن
بیمار و کمیسیون پزشک پیش‌تر فقط یک جمله در پرامپت سیستمی بود؛ پرامپت کنترل
دسترسی نیست — هم می‌توان مدل را از آن منصرف کرد و هم همان داده یک فراخوانی
REST آن‌طرف‌تر بود. در مقابل، **محدوده موضوعی** دستیار عمداً در پرامپت مانده،
چون هزینه شکستش یک فراخوانی هدررفته است، نه نشت داده.

## آزمون‌ها

```bash
cd backend && ../.venv/bin/python -m pytest -q      # ۱۲۳ آزمون
```

آزمون‌های یکپارچگی به یک MongoDB محلی نیاز دارند و در نبودش skip می‌شوند؛
`TEST_MONGO_URL` آدرس را تغییر می‌دهد.

```bash
npm run build --prefix frontend                     # بررسی ساخت تولیدی
node frontend/src/shared/lib/jalali.test.mjs
```

## بازتولید داده

```bash
python scripts/generate_data.py       # بذر ثابت ⇒ خروجی یکسان
```

مولد، قوانین کسب‌وکار را هنگام تولید اعمال و پس از آن دوباره بررسی می‌کند:
هیچ نوبتی خارج ساعات کاری یا در روز تعطیل، هیچ جلسه‌ای بدون نوبت متناظر، و
هیچ فاکتوری بدون طرح درمان.

## عیب‌یابی

| نشانه | علت |
|---|---|
| `required variable API_DB_PASSWORD is missing` | در `.env` تنظیم نشده — بخش راه‌اندازی سریع |
| ۵۹ آزمون skip شد | MongoDB بالا نیست |
| ورود با ۴۲۹ رد می‌شود | قفل ۱۵ دقیقه‌ای پس از ۵ تلاش ناموفق |
| تب دستیار غیرفعال است | `AVALAI_API_KEY` تنظیم نشده |
| نموداری فیلتر را اعمال نکرده | عمدی است — توضیحش زیر همان نمودار آمده |
