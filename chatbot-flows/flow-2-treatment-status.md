# فلو ۲ — پیگیری وضعیت درمان (Treatment Status)

## Role & Goal

**نقش:** بیمار (Patient)

**هدف:** بیمار بدون مراجعه حضوری، وضعیت طرح درمان جاری خود، جلسات انجام‌شده و باقی‌مانده، و مانده حساب مالی‌اش را ببیند.

**پیش‌فرض:** بیمار حداقل یک `TreatmentPlan` ثبت‌شده دارد. اگر نداشته باشد، ربات او را به [فلو ۱ — رزرو نوبت](flow-1-book-appointment.md) هدایت می‌کند.

## Validation Rules per Input

| ورودی | قانون اعتبارسنجی | منبع |
|---|---|---|
| `national_code` | ۱۰ رقم، رقم کنترل mod-11 معتبر (همان الگوریتم فلو ۱) | الگوریتم کد ملی |
| `national_code` | باید در `Patient` موجود باشد | `Patient.national_code` |
| ۴ رقم آخر موبایل | دقیقاً ۴ رقم؛ باید با `RIGHT(Patient.phone, 4)` مطابقت کند | `Patient.phone` |
| انتخاب منو | عدد ۱ تا ۴، یا کلیدواژه (جلسات / نوبت / مالی / خروج) | — |
| انتخاب طرح (اگر چند طرح) | `plan_id` باید متعلق به همان `patient_id` باشد | `TreatmentPlan.patient_id` |

### قوانین محاسباتی (نمایش، نه ذخیره)

```
درصد پیشرفت = COUNT(TreatmentSession WHERE plan_id = ?)
             / (تعداد جلسات برنامه‌ریزی‌شده طرح) × 100

مانده حساب   = Invoice.patient_share − SUM(Payment.amount WHERE invoice_id = ?)

نوبت بعدی    = MIN(Appointment.scheduled_datetime)
               WHERE patient_id = ? AND status = 'رزرو'
                 AND scheduled_datetime > NOW()
```

**قالب کد رهگیری استعلام:** `INQ-YYYYMMDD-NNNN`

| بخش | معنی |
|---|---|

## Voiceflow Implementation Notes

### ساختار بلوک‌ها

```
[Start]
  └─ Capture → {national_code} → Code Block: validateNationalCode()
  └─ API: GET /patients?national_code={national_code}
       ├─ 404 → Jump to [Flow 3]
       └─ 200 → Set {patient_id}, {patient_name}, {phone_last4}
  └─ Capture → {input_last4}
       └─ Condition: {input_last4} == {phone_last4}
            ├─ خیر → {auth_retry}+1 → Condition >= 3 ? [Lockout] : تکرار
            └─ بله → ادامه
  └─ API: GET /patients/{patient_id}/plans?status=active
       ├─ آرایه خالی → Speak + Jump to [Flow 1]
       ├─ ۱ عضو  → Set {plan_id}
       └─ چند عضو → Dynamic Buttons → {plan_id}
  └─ API: GET /plans/{plan_id}/summary   ← یک فراخوانی، همه داده‌ها
  └─ Speak: کارت خلاصه طرح
  └─ [MENU] Buttons: ۱ جلسات / ۲ نوبت بعدی / ۳ مالی / ۴ خروج
       ├─ ۱ → Speak لیست جلسات → بازگشت به [MENU]
       ├─ ۲ → Speak نوبت بعدی   → بازگشت به [MENU]
       ├─ ۳ → Speak وضعیت مالی  → بازگشت به [MENU]
       └─ ۴ → [End]
```

### نکات پیاده‌سازی

1. **یک فراخوانی API، نه چهار.** یک اندپوینت `GET /plans/{id}/summary` بسازید که طرح، جلسات، نوبت بعدی و وضعیت مالی را یک‌جا برگرداند. سپس هر گزینه منو فقط از متغیرهای ذخیره‌شده می‌خواند — بدون رفت‌وبرگشت شبکه.
2. **احراز هویت دومرحله‌ای الزامی است.** داده بالینی و مالی است؛ کد ملی به‌تنهایی کافی نیست. ۴ رقم آخر موبایل حداقلِ قابل قبول است.
3. **قفل پس از ۳ خطا.** `auth_retry` را در متغیر ذخیره کنید و پس از سه خطا مسیر را به [End] ببرید — نه بازگشت به ابتدا.
4. **حلقه منو.** پس از هر گزینه به `[MENU]` برگردید، نه به `[Start]`؛ در غیر این صورت کاربر مجبور به احراز هویت مجدد می‌شود.
5. **نوار پیشرفت متنی.** با `✅` و `⬜` بسازید (`repeat` در Code Block) — در همه کلاینت‌ها بدون وابستگی به فونت رندر می‌شود.
6. **قالب‌بندی مبلغ.** جداکننده هزارگان فارسی (`٬`) را در Code Block اعمال کنید: `n.toLocaleString('fa-IR')`.
7. **تبدیل تاریخ.** همه تاریخ‌های خروجی پایگاه داده میلادی هستند؛ پیش از نمایش به شمسی تبدیل کنید.
8. **بدون Write.** مطمئن شوید هیچ بلوک این فلو متد `POST`/`PATCH` صدا نمی‌زند — این فلو باید کاملاً خواندنی بماند.
