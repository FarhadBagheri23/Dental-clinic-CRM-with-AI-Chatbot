# فلو ۳ — ثبت بیمار جدید (Register Patient)

## Role & Goal

**نقش:** پذیرش (Receptionist) — کاربر `Staff` با `role = 'پذیرش'`

**هدف:** متصدی پذیرش پرونده یک بیمار جدید را در سیستم ثبت کند، بیمه او را متصل نماید و در صورت تمایل بلافاصله اولین نوبت را رزرو کند.

**نکته مهم:** برخلاف فلوهای ۱ و ۲، کاربر این فلو **کارمند** است نه بیمار. بنابراین ابتدا باید احراز هویت کارمند انجام شود.

---

## Entities Touched (from ERD)

| موجودیت | نوع دسترسی | فیلدهای درگیر |
|---|---|---|
| `Staff` | خواندن | `staff_id`, `role` — احراز هویت اپراتور |
| `Patient` | **نوشتن** | `national_code`, `first_name`, `last_name`, `birth_date`, `gender`, `phone`, `address`, `blood_type`, `allergies`, `insurance_id`, `registration_date` |
| `Insurance` | خواندن | `insurance_id`, `company_name`, `coverage_percentage`, `expiry_date` |
| `Appointment` | **نوشتن (اختیاری)** | در صورت رزرو نوبت اولیه — انتقال به [فلو ۱](flow-1-book-appointment.md) |

**رکورد ایجادشده:** یک ردیف در `Patient` با `registration_date = CURRENT_DATE`.

### مقادیر تولیدشده توسط سیستم (نه ورودی کاربر)

```
patient_id        = AUTO_INCREMENT
registration_date = CURRENT_DATE
```

> ⚠️ `registration_date` هرگز از کاربر گرفته نمی‌شود. قانون
> `appointment.scheduled_datetime > patient.registration_date` به آن وابسته است؛
> اگر اپراتور بتواند تاریخ گذشته وارد کند، آن قانون قابل دور زدن می‌شود.

```

**قالب شماره پرونده:** `PAT-NNNNN`

| بخش | معنی | مثال |
|---|---|---|
| `PAT` | پیشوند ثابت بیمار (Patient) | `PAT` |
| `NNNNN` | `patient_id` با صفر پیشرو تا ۵ رقم | `00501` |

**قالب کد پیگیری ثبت:** `REG-YYYYMMDD-NNNN` — تاریخ شمسی ثبت + شماره ترتیبی ثبت‌نام در آن روز.

**رکورد درج‌شده در پایگاه داده:**

```sql

## Voiceflow Implementation Notes

### ساختار بلوک‌ها

```
[Start]
  └─ Capture → {staff_id}
       └─ API: GET /staff/{staff_id}
            ├─ 404          → خطا → تکرار (حداکثر ۳)
            ├─ role ≠ پذیرش → Speak «مجوز ندارید» → [End]
            └─ OK           → Set {staff_name}
  └─ [STEP_1] Capture → {national_code}
       └─ Code Block: validateNationalCode()
       └─ API: GET /patients?national_code={national_code}
            ├─ 200 (پیدا شد) → Speak «تکراری» → Buttons → [Flow 2] یا [End]
            └─ 404 (آزاد)    → ادامه
  └─ [STEP_2..9] زنجیره Capture با یک Code Block اعتبارسنجی برای هر مرحله
  └─ API: GET /insurance?active=true → Dynamic Buttons → {insurance_id}
       └─ Condition: expiry_date < today ? هشدار : ادامه
  └─ Speak: کارت بازبینی (از متغیرها ساخته می‌شود)
  └─ Buttons: بله / خیر / ویرایش
       ├─ ویرایش → Capture شماره فیلد → Jump به [STEP_N]
       ├─ خیر    → Speak «لغو شد» → [End]
       └─ بله    → API: POST /patients
            ├─ 409 → Speak «کد ملی تکراری» (شرایط مسابقه‌ای) → [STEP_1]
            ├─ 500 → Speak «DB-500» → [End]
            └─ 201 → Set {patient_id}, {file_number} → Speak موفقیت
  └─ Buttons: رزرو نوبت؟ → [Flow 1] با {patient_id} یا [End]
```

### نکات پیاده‌سازی

1. **احراز هویت اپراتور، نه بیمار.** بررسی نقش (`role = 'پذیرش'`) را در **سرور** انجام دهید، نه فقط در ربات؛ در غیر این صورت هر کسی با یک `staff_id` معتبر می‌تواند بیمار ثبت کند.
2. **بررسی تکراری‌بودن را زودتر انجام دهید.** استعلام یکتایی کد ملی باید در مرحله ۱ باشد، نه در انتها — در غیر این صورت اپراتور ۹ فیلد را پر می‌کند و در آخر خطا می‌گیرد.
3. **قید یکتایی در پایگاه داده الزامی است.** بررسی ربات جلوی رقابت هم‌زمان دو اپراتور را نمی‌گیرد. `UNIQUE` روی `national_code` تنها تضمین واقعی است؛ ربات باید `409` را مدیریت کند.
4. **`registration_date` را از کاربر نگیرید.** آن را در سرور با `CURRENT_DATE` بگذارید (بند بالا در بخش اعتبارسنجی).
5. **مسیر «ویرایش» را با پرش بسازید،** نه با شروع مجدد فلو. یک متغیر `edit_target` بگذارید و با Condition به `[STEP_N]` بپرید، سپس مستقیم به کارت بازبینی برگردید.
6. **فیلدهای اختیاری را صریح کنید.** برای `address`، `blood_type` و `allergies` کلیدواژه «رد» را بپذیرید و به `NULL` تبدیل کنید — نه رشته خالی.
7. **حساسیت دارویی را برجسته کنید.** هر جا پرونده نمایش داده می‌شود، `allergies` باید با هشدار قرمز رندر شود. این یک تصمیم ایمنی بالینی است، نه تزئین رابط کاربری.
8. **نرمال‌سازی ارقام.** اپراتور ممکن است ارقام فارسی (`۰۹۱۲`) تایپ کند؛ پیش از هر اعتبارسنجی به لاتین تبدیل کنید.
9. **تبدیل تاریخ شمسی به میلادی** پیش از `POST` — ستون `birth_date` از نوع `date` میلادی است.
10. **دکمه «انصراف» سراسری.** در هر Capture یک Intent با نام `cancel` تعریف کنید که به `[End]` می‌رود و متغیرها را پاک می‌کند.
