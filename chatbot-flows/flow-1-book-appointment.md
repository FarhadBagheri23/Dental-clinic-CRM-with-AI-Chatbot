# فلو ۱ — رزرو نوبت (Book Appointment)

## Role & Goal

**نقش:** بیمار (Patient)

**هدف:** بیمار بدون تماس تلفنی با کلینیک، یک نوبت جدید در تقویم رزرو کند و کد پیگیری دریافت نماید.

**پیش‌فرض:** بیمار قبلاً در کلینیک ثبت‌نام کرده و کد ملی او در جدول `Patient` موجود است. اگر ثبت‌نام نکرده باشد، به [فلو ۳ — ثبت بیمار جدید](flow-3-register-patient.md) هدایت می‌شود.

---

## Entities Touched (from ERD)

| موجودیت | نوع دسترسی | فیلدهای درگیر |
|---|---|---|
| `Patient` | خواندن | `patient_id`, `national_code`, `first_name`, `last_name`, `phone`, `registration_date` |
| `Service` | خواندن | `service_id`, `name`, `category`, `base_price`, `duration_minutes` |
| `Dentist` | خواندن | `dentist_id`, `first_name`, `last_name`, `specialty` |
| `Appointment` | **نوشتن** | `patient_id`, `dentist_id`, `created_by_staff_id` (خالی = رزرو آنلاین)، `scheduled_datetime`, `status`, `chair_number` |

**رکورد ایجادشده:** یک ردیف در `Appointment` با `status = "رزرو"`.

## Validation Rules per Input

| ورودی | قانون اعتبارسنجی | منبع |
|---|---|---|
| `national_code` | دقیقاً ۱۰ رقم؛ فقط عدد؛ همه ارقام یکسان نباشد؛ **رقم کنترل mod-11 معتبر** | الگوریتم کد ملی ایران |
| `national_code` | باید در جدول `Patient` وجود داشته باشد | `SELECT patient_id FROM Patient WHERE national_code = ?` |
| انتخاب خدمت | عدد ۱..۷ یا نام موجود در `Service.name` | `Service` |
| انتخاب پزشک | `dentist_id` معتبر و `Dentist.specialty` متناسب با دسته خدمت | `Dentist` |
| تاریخ | فرمت `YYYY/MM/DD` شمسی؛ **بزرگ‌تر از امروز**؛ حداکثر ۹۰ روز آینده؛ روز جمعه نباشد | تقویم کلینیک |
| تاریخ | باید بزرگ‌تر از `Patient.registration_date` باشد | قانون کسب‌وکار ERD |
| ساعت | فقط بازه **۰۸:۰۰ تا ۲۱:۰۰**، روی گرید ۳۰ دقیقه‌ای (`:00` یا `:30`) | قانون کسب‌وکار |
| ساعت | اسلات باید برای آن **پزشک** و آن **یونیت** آزاد باشد | `Appointment` (بدون رزرو تکراری) |
| تأیید نهایی | فقط «بله / آره / تأیید» یا «خیر / نه / انصراف» | — |

### الگوریتم اعتبارسنجی کد ملی

```
ورودی: رشته ۱۰ رقمی d[0..9]
اگر طول ≠ ۱۰ یا غیرعددی → نامعتبر
اگر همه ارقام یکسان → نامعتبر
s = Σ d[i] × (10 − i)   برای i = 0..8
r = s mod 11
control = r        اگر r < 2
control = 11 − r   اگر r ≥ 2
معتبر است اگر d[9] == control
```

```
کد پیگیری: APT-14050520-0473
بیمار:     مریم رضایی
خدمت:      جرم‌گیری
پزشک:      دکتر علی محمدی
تاریخ:     سه‌شنبه ۲۰ مرداد ۱۴۰۵ — ساعت ۱۰:۰۰
یونیت:     ۳
```

**قالب کد پیگیری:** `APT-YYYYMMDD-NNNN`

| بخش | معنی | مثال |
|---|---|---|
| `APT` | پیشوند ثابت نوبت (Appointment) | `APT` |
| `YYYYMMDD` | تاریخ شمسی نوبت بدون جداکننده | `14050520` |
| `NNNN` | چهار رقم آخر `appointment_id` با صفر پیشرو | `0473` |

**رکورد درج‌شده در پایگاه داده:**

```sql
INSERT INTO Appointment
  (patient_id, dentist_id, created_by_staff_id,
   scheduled_datetime, status, chair_number)
VALUES
  (:patient_id, :dentist_id, NULL, '2026-08-11 10:00:00', 'رزرو', :chair);
```

> `created_by_staff_id` برای رزروهای آنلاین `NULL` می‌ماند؛ همین فیلد در داشبورد
> سهم «رزرو آنلاین» را از «رزرو حضوری توسط پذیرش» جدا می‌کند.

## Voiceflow Implementation Notes

### ساختار بلوک‌ها

```
[Start]
  └─ Speak: خوش‌آمدگویی
  └─ Capture → {national_code}
       └─ Code Block: validateNationalCode()      ← اعتبارسنجی mod-11
            ├─ نامعتبر → Set {retry}+1 → Condition {retry} >= 3 ? [End] : بازگشت
            └─ معتبر  → API: GET /patients?national_code={national_code}
                 ├─ 404 → Speak + Jump to [Flow 3 — ثبت بیمار]
                 └─ 200 → Set {patient_id}, {patient_name}
  └─ Buttons: انتخاب خدمت → {service_id}
  └─ API: GET /dentists?specialty={service_specialty} → Buttons → {dentist_id}
  └─ Capture → {date_jalali}
       └─ Code Block: jalaliToGregorian() + validateDate()
  └─ API: GET /slots?date={date}&dentist={dentist_id} → Buttons (dynamic) → {slot}
  └─ Speak: خلاصه رزرو
  └─ Buttons: بله / خیر
       ├─ خیر → Jump به مرحله تاریخ
       └─ بله → API: POST /appointments
            ├─ 409 Conflict → Speak «اسلات پر شد» → بازگشت به لیست اسلات‌ها
            └─ 201 → Set {tracking_code} → Speak: پیام موفقیت
  └─ Buttons: کار دیگری دارید؟ → [Start] یا [End]
```

### نکات پیاده‌سازی

1. **متغیرهای Voiceflow:** `national_code`, `patient_id`, `patient_name`, `service_id`, `service_name`, `dentist_id`, `dentist_name`, `date_jalali`, `date_gregorian`, `slot`, `chair_number`, `tracking_code`, `retry`.
2. **اعتبارسنجی سمت ربات:** الگوریتم کد ملی و بررسی گرید ۳۰ دقیقه‌ای را در **Code Block** (JavaScript) بگذارید، نه در API — بازخورد فوری و بدون رفت‌وبرگشت شبکه.
3. **تبدیل تاریخ:** شمسی ← میلادی را در همان Code Block انجام دهید؛ پایگاه داده فقط میلادی می‌شناسد (`scheduled_datetime` از نوع `datetime`).
4. **دکمه‌های پویا:** فهرست پزشکان و اسلات‌های خالی را با **Dynamic Buttons** از پاسخ API بسازید؛ آن‌ها را دستی ننویسید.
5. **جلوگیری از رزرو تکراری:** بررسی نهایی خالی‌بودن اسلات باید در سرور (قید یکتایی روی `dentist_id + scheduled_datetime` و `chair_number + scheduled_datetime`) انجام شود. ربات باید پاسخ `409` را مدیریت کند.
6. **شمارنده تلاش:** `retry` را در ابتدای هر مرحله صفر و در هر خطا یک واحد زیاد کنید؛ در ۳ به مسیر «تماس با پشتیبانی» بروید.
7. **No-Match / No-Reply:** برای هر Capture حداقل دو پیام Reprompt متفاوت تعریف کنید تا گفت‌وگو در حلقه تکراری گیر نکند.
8. **RTL و اعداد فارسی:** ارقام ورودی کاربر ممکن است فارسی (`۰۱۲۳`) یا عربی (`٠١٢٣`) باشد؛ در ابتدای هر Code Block آن‌ها را به لاتین نرمال‌سازی کنید.
