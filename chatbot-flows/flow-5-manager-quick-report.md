# فلو ۵ — گزارش سریع مدیریتی (Manager Quick Report)

## Role & Goal

**نقش:** مدیر کلینیک (Manager)

**هدف:** مدیر بدون باز کردن داشبورد Looker Studio، شاخص‌های کلیدی کلینیک را در قالب گفت‌وگو و روی موبایل ببیند — درآمد، مطالبات، عملکرد پزشکان، نرخ غیبت و وضعیت انبار.

**جایگاه نسبت به داشبورد:** این فلو **جایگزین** داشبورد نیست، مکمل آن است. داشبورد برای تحلیل عمیق و روند بلندمدت است؛ این فلو برای پاسخ سریع به «الان وضعیت چطور است؟» در حال حرکت.

> اعداد نمونه در این سند از خروجی واقعی `scripts/generate_data.py` استخراج شده‌اند
> (دوره: ۱۲ ماه گذشته، ۲٬۴۰۰ جلسه، ۴۰۰ فاکتور).

## Validation Rules per Input

| ورودی | قانون اعتبارسنجی | منبع |
|---|---|---|
| `staff_id` | باید در `Staff` موجود باشد | `Staff.staff_id` |
| `staff_id` | **`role` باید `'مدیر'` یا `'حسابدار'` باشد** | `Staff.role` |
| رمز عبور | مطابقت با هش ذخیره‌شده؛ **هرگز متن ساده مقایسه نشود** | جدول احراز هویت (خارج از ERD) |
| انتخاب گزارش | عدد ۱ تا ۶ یا کلیدواژه (مالی / پزشکان / خدمات / نوبت / انبار / کامل) | — |
| انتخاب بازه | عدد ۱ تا ۶ | — |
| بازه دلخواه | `از_تاریخ <= تا_تاریخ`؛ هر دو در گذشته یا امروز؛ حداکثر ۳۶۵ روز | منطق کسب‌وکار |
| نام پزشک (جزئیات) | باید در `Dentist` موجود باشد | `Dentist` |

### فرمول‌های محاسباتی گزارش

```sql
-- درآمد کل
SELECT SUM(total_amount) FROM Invoice WHERE issue_date BETWEEN :from AND :to;

-- وصولی
SELECT SUM(p.amount) FROM Payment p
  JOIN Invoice i ON p.invoice_id = i.invoice_id
 WHERE i.issue_date BETWEEN :from AND :to;

-- مطالبات معوق  =  Σ سهم بیمار − Σ پرداختی
SELECT SUM(i.patient_share) - COALESCE(SUM(p.amount), 0) ...

-- درآمد هر پزشک (از جلسات، نه از فاکتور)
SELECT d.dentist_id, SUM(s.actual_cost)
  FROM TreatmentSession s
  JOIN TreatmentPlan  t ON s.plan_id = t.plan_id
  JOIN Dentist        d ON t.dentist_id = d.dentist_id
 WHERE s.session_date BETWEEN :from AND :to
 GROUP BY d.dentist_id ORDER BY 2 DESC;

-- نرخ غیبت
SELECT COUNT(*) FILTER (WHERE status = 'غایب') * 100.0 / COUNT(*)
  FROM Appointment WHERE scheduled_datetime BETWEEN :from AND :to;

-- اقلام زیر حد سفارش
SELECT name, stock_quantity, min_stock_level
  FROM Consumable WHERE stock_quantity <= min_stock_level;
```

> ⚠️ **درآمد پزشک از `TreatmentSession.actual_cost` محاسبه می‌شود، نه از `Invoice`.**
> فاکتور به `TreatmentPlan` وصل است و یک طرح یک پزشک دارد؛ اما جلسه‌ها سطح
> ریزتری هستند و اجازه بازه‌بندی زمانی دقیق‌تر می‌دهند.

## Voiceflow Implementation Notes

### ساختار بلوک‌ها

```
[Start]
  └─ Capture → {staff_id}
  └─ Capture (mask) → {password}
       └─ API: POST /auth/staff  { staff_id, password }
            ├─ 401 → {auth_retry}+1 → >= 3 ? [Lockout] : تکرار
            ├─ 403 (نقش غیرمجاز) → Speak + لاگ → [End]
            └─ 200 → Set {token}, {manager_name}, {role}
  └─ [MENU] Buttons: ۱..۶
  └─ [PERIOD] Buttons: امروز/هفته/ماه/۳ماه/۱۲ماه/دلخواه
       └─ دلخواه → Capture {from}, {to} → Code Block: validateRange()
  └─ API: GET /reports/{type}?from={from}&to={to}
            Header: Authorization: Bearer {token}
       ├─ 204 (بدون داده) → Speak → [PERIOD]
       ├─ 408 (تایم‌اوت)   → Speak → [PERIOD]
       └─ 200 → Code Block: formatReportCard() → Speak
  └─ Buttons: جزئیات بیشتر / منوی اصلی / خروج
       ├─ جزئیات   → API فرعی → Speak → [MENU]
       ├─ منوی اصلی → [MENU]
       └─ خروج     → [End]
```

### نکات پیاده‌سازی

1. **تجمیع در پایگاه داده، نه در ربات.** هرگز ۲٬۴۰۰ ردیف جلسه را به ربات نفرستید تا آنجا جمع بزند. `GROUP BY` و `SUM` را در SQL انجام دهید و فقط چند عدد نهایی برگردانید.
2. **احراز هویت دو عاملی (کد + رمز) الزامی است.** این فلو کل تصویر مالی کلینیک را برمی‌گرداند؛ کد پرسنلی به‌تنهایی کافی نیست. رمز را با Capture ماسک‌دار بگیرید.
3. **کنترل دسترسی در سرور.** بررسی `role` باید در اندپوینت `/reports/*` باشد، نه فقط در ربات. یک توکن با نقش `دستیار` باید `403` بگیرد.
4. **رمز را هش‌شده مقایسه کنید** (bcrypt/argon2) و هرگز در متغیر Voiceflow ذخیره نکنید — فقط توکن بازگشتی را نگه دارید.
5. **کش کوتاه‌مدت.** گزارش ۱۲ ماهه سنگین است و در طول روز تغییر چندانی نمی‌کند؛ نتیجه را ۱۵ دقیقه کش کنید تا مدیر با هر بار باز کردن منو پرس‌وجوی سنگین اجرا نشود.
6. **ایندکس‌های لازم** روی `Invoice.issue_date`، `TreatmentSession.session_date` و `Appointment.scheduled_datetime` بسازید — همه گزارش‌ها روی این سه ستون بازه‌بندی می‌کنند.
7. **قالب‌بندی جدول با فونت یکنواخت.** جدول‌ها را داخل بلوک ` ``` ` بگذارید تا ستون‌ها در موبایل به هم نریزند.
8. **حریم خصوصی.** اندپوینت‌های این فلو نباید هیچ `patient_id`، نام بیمار یا کد ملی برگردانند — فقط اعداد تجمیعی. این را در خود API اعمال کنید، نه در ربات.
9. **تحلیل، نه فقط عدد.** بعد از هر جدول یک جمله «📌 نکته» بگذارید. عددِ خالی تصمیم نمی‌سازد؛ تفسیر می‌سازد. این تفاوت یک گزارش مدیریتی با یک خروجی خام است.
10. **لینک به داشبورد.** در انتهای هر گزارش لینک صفحه متناظر Looker Studio را بدهید تا مدیر برای تحلیل عمیق‌تر یک کلیک فاصله داشته باشد.
